# ブロックス全置きチャレンジ

20×20の盤面に、青・黄・赤・緑の各21種類、合計84ピースを置く1人用ゲームです。HTML / CSS / JavaScriptのみで動き、ビルド・外部通信・ライブラリは不要です。

## 起動

`index.html` をブラウザで開いてください。配布する場合は `index.html`、`style.css`、`engine.js`、`solution.js`、`app.js` を同じフォルダーに置きます。

## ルール

- 青は左上、黄は右上、赤は右下、緑は左下から始めます。各色の初手は、その色の ★ のマスを含めます。
- 2手目以降は、配置済みの同色ピースと角で接する必要があります。
- 同色のピース同士は辺で接してはいけません。異色同士は辺・角のどちらで接しても構いません。
- 重複・盤外配置は禁止です。各色は21種類を1枚ずつ使用できます。
- 色や配置順は自由です。全84ピースを合法的に置くとクリアです。
- ピースの合計面積は356マス。400マス全体を埋めるゲームではありません。

## 操作

1. 色を選び、未使用ピースを選択します。色のボタンに各色の配置数・残数が表示されます。
2. 左回転・右回転・左右反転で向きを変えます。
3. ピースの「●」の位置を盤面上でタップ／クリックして配置予告を出します。点が付いたマスは、現在の向きで置ける基準位置です。
4. 必要なら矢印ボタンで1マスずつ調整し、「ここに置く」で確定します。不正な位置には確定できず、理由が表示されます。

PCではマウスを重ねると配置予告が表示されます。盤面にフォーカスした状態で矢印キーを使うと隣のマスへ移動し、Enter / Spaceで位置を選べます。

ピース一覧には選択中の色の全21種類が表示され、配置済みは「✓」付きで選択不可になります。「1手戻す」は色を問わず直前の配置を戻し、そのピースを再選択します。「最初から」は確認後に4色すべてをリセットします。再読み込み・ページを閉じた場合も配置はリセットされます。

## 構成と流用元

`blokus-puzzle` の21種類のピース定義、正規化・回転・反転・向き列挙・基準マスによる座標変換、ピースのミニ表示・合法位置表示を流用しています。元リポジトリは変更していません。問題選択・難易度・問題データ・アクセス記録は含みません。管理者用の解答確認は、全84ピースの検証済みデータを使う専用機能です。

- `engine.js`: ピース定義、変形、4色の純粋な配置判定、合法な84手のクリア判定。
- `app.js`: 在庫、操作、配置予告、履歴、画面表示。
- `style.css`: 元のシンプルな配色を基本にした、PC・スマホ向けレイアウト。

## 検証

Node.jsで実行します。

```sh
node tests/rules.cjs
```

21種類の独立列挙との一致、回転・反転、四隅、同色の辺接触禁止、異色の辺接触許可、角接触、重複、盤外、同色同種の再使用禁止、不正なクリアの拒否を検証します。

ブラウザテストにはPlaywrightとGoogle Chromeが必要です（ゲーム自体には不要）。

```sh
node tests/browser.cjs
```

320px・390pxのスマホ相当と1280pxのPC幅で、タップ／クリック、配置予告・確定、1マス移動、回転・反転、4色の初手、接触判定、1手戻す、リセットの承認／キャンセル、横はみ出し・JavaScriptエラー・外部通信がないことを確認します。スクリーンショットは一時ディレクトリに保存します。スマホ実機での検証は行っていません。

## 管理者用の解答確認

タイトルを2秒以内に5回クリック／タップすると管理者モードをON／OFFできます。ONのときだけ「解答を表示」が現れます。解答表示中は通常操作を無効化し、クリアにはしません。「解答を閉じる」またはタイトル5回でOFFにすると、直前の配置・色・選択ピース・向き・配置予告・メッセージを復元します。「1手戻す」の履歴も保持します。再読み込みで管理者モードはOFFになります。

これは `blokus-puzzle` と同じ隠し操作方式で、ログイン認証ではありません。解答データは静的ファイルとして配信されます。

### 解答の出典・復元・検証

採用した解答は [Toby Gottfried氏の18×20公開解](https://www.gottfriedville.net/blokus/18x20dtl.htm) の中央パネルに基づきます。[元画像](https://www.gottfriedville.net/blokus/18x20dtl.gif) をプログラムで読み取り、20列×18行の各マス中央3×3画素の色が一致することを確認しました。画像自体は同梱せず、抽出グリッド・出典URL・画像SHA-256・抽出位置を `analysis/reference-grid.json` に記録しています。

同色の辺でつながる成分をピースとして抽出し、回転・反転を含めて現在の21種類へ自動対応付けしました。手入力したピース座標ではありません。公開解の色は開始隅に合わせて割り当て直しています。

単純な埋め込みでは下側の開始位置が2行ずれます。そのため下側2色について、開始隅を覆うI5の全候補と、元のI5の位置に収まるI3の全候補を列挙し、ゲーム本体の判定に通る組み合わせを探索しました。計4ピースだけを変更しています。最終配置は青(0,0)・黄(19,0)・赤(19,19)・緑(0,19)から合法的に配置できます。元と調整後の座標は `analysis/solution.json` に記録しています。

検証結果：**84ピース・各色21種類を1回ずつ、356マス占有、44マス空き**。独立した形状・接触グラフの検証と、ゲーム本体の `check` による84手の再生・`isComplete` の成功を確認しています。異色の辺接触382か所・角接触394か所も合法として扱っています（マス同士の接触数）。

- `tools/extract-reference.py`: 元画像から色グリッドを自動抽出。再抽出だけにPillowが必要。
- `tools/reconstruct-solution.cjs`: グリッドから形状を同定し、下側の開始隅を局所探索で調整。合法な配置順を作り、検証後に保存。
- `tools/verify-solution.cjs`: 在庫、形状、整数座標、盤内、重複、各色の初手、同色の辺接触禁止、開始点からの角接触グラフの連結を独立検証し、さらにゲーム本体で再生。
- `tools/export-solution.cjs`: 検証に成功したデータだけを `solution.js` に出力。配布時はこのファイルも必要。
- `tests/solution.cjs`: 参照グリッドからの再構成・保存データ・配信データの一致、全条件の検証、破損データの拒否。
- `tests/admin-browser.cjs`: スマホ相当・PCで5回判定と時間切れ、解答盤面の一致、操作禁止、クリア抑制、状態・Undoの復元、再読み込みでOFF、通常操作経由の84手クリアを確認。

保存済みグリッドからの再構成・検証・出力はNode.jsだけで実行できます。ブラウザ内で探索や通信は行いません。

```sh
node tools/reconstruct-solution.cjs
node tools/verify-solution.cjs
node tools/export-solution.cjs
node tests/rules.cjs
node tests/solution.cjs
node tests/browser.cjs
node tests/admin-browser.cjs
```

最後の2つのブラウザテストにはPlaywrightとGoogle Chromeが必要です。元画像からの抽出まで再現する場合は、開発用環境へ `tools/requirements.txt` を導入し、ダウンロードした画像を次のように指定します。

```sh
python3 tools/extract-reference.py /path/to/18x20dtl.gif analysis/reference-grid.json
```

5回タップ方式は認証ではないため、公開サイト上で解答ファイルへのアクセス自体を制限する機能はありません。
